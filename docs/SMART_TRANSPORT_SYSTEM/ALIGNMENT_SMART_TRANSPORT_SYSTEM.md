# ALIGNMENT_SMART_TRANSPORT_SYSTEM

## 1. 项目背景分析

### 1.1 项目概述
智能运力系统是为解决目前全省派车集中化需求，从全流程进行管控跟踪，包括任务创建、审核、分配、执行、结算等环节，形成日报表，月结算清单，并发起线上审核，压缩报账流程，管控报账全生命周期，再通过数据化实现单车核算，形成邮路优化方案，实施智能化派车，基于Python/Flask构建后端RESTful API，前端使用Vue.js实现单页应用。

### 1.2 技术栈选择
- **前端**: Vue.js 3 + TypeScript + Vite
- **后端**: Flask + SQLAlchemy + Flask-RESTful
- **数据库**: SQLite（开发）/ PostgreSQL（生产）
- **认证**: JWT + Flask-Login
- **架构**: 前后端分离 + 服务层设计模式

### 1.3 现有问题分析
基于现有文档分析，上个版本存在以下主要问题：
1. 数据库设计不够规范，存在冗余字段
2. API接口设计不够RESTful，状态管理复杂
3. 权限控制机制不够完善
4. 代码组织结构不够清晰，可维护性差
5. 缺乏完整的测试覆盖

## 2. 需求理解确认

### 2.1 核心业务需求
- **双轨派车流程**: 支持轨道A（需要审核）和轨道B（直接派车）
- **运费流程优化**: 供应商-车间车型审批实时化，自动核实运费，电子结算单生成
- **单车核算**: 精准的单车成本核算，自动生成日报总结，预警信息推送
- **智能派车预测**: 基于历史数据预测各路向车型需求，合理安排加班车辆
- **任务全生命周期管理**: 从创建到完成的完整任务管理
- **多角色权限控制**: 超级管理员、区域调度员、车间地调、供应商
- **车辆信息管理**: 车辆基本信息和容积数据管理（5吨、8吨、12吨、20吨、30吨、40吨A、40吨B）
- **公司管理**: 承运商公司信息管理
- **状态流转**: 完整的任务状态流转和历史记录
- **电子流程审批**: 数据流转 + 多角色审核 + 飞书协同 + 电子签名

### 2.2 用户角色定义
1. **超级管理员**: 系统所有功能的完全访问权限
2. **区域调度员**: 创建和管理派车任务，审核任务，分派车辆，运费审核
3. **车间地调**: 创建派车任务，查看任务状态，车型审批确认
4. **供应商**: 查看分配给自己的任务，确认响应任务，填写车辆信息，确认结算单
5. **财务人员**: 审核结算单，电子签名确认

### 2.3 业务流程
#### 轨道A流程（需要审核）
1. 任务创建 → 2. 待调度员审核 → 3. 审核通过 → 4. 待供应商响应 → 5. 供应商响应 → 6. 任务完成

#### 轨道B流程（直接派车）
1. 任务创建 → 2. 待供应商响应 → 3. 供应商响应 → 4. 任务完成
